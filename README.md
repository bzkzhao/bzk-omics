# bzk Omics

A local-first knowledge graph for post-translational modification proteomics, which treats modification identity as an evidenced inference rather than an assertion.

A diGly site stays ambiguous between ubiquitin, NEDD8 and ISG15 until knockout, mutant or interactome evidence resolves it. The enzyme that wrote or erased it is recorded only where a perturbation experiment supports the claim. Every result traces back to the raw file, the search parameters, and the human judgement used to reconstruct the experimental design.

## Why this exists

Ubiquitin, NEDD8, ISG15 and FAT10 all leave an identical K-ε-GG remnant after tryptic digestion. The field's default assumption that a diGly site is ubiquitin holds at baseline and fails under interferon stimulation — the exact condition of interest in ISGylation biology. Existing tools either report the assumption as fact or leave it to prose in a discussion section.

The same pattern recurs. Which protein a shared peptide came from, which enzyme placed the mark, whether a value was measured or generated by an imputation step, how the experimental design was reconstructed for a public dataset — all are inferences routinely presented as measurements. This project models them as inferences, each with a basis, a confidence, and an evidence chain.

Full rationale in [`VISION.md`](VISION.md). Not repeated here.

## Exploratory work

Three notebooks, run in Google Colab against public PRIDE data. Each produced findings that changed the schema; those findings are recorded in [`ROADMAP.md`](ROADMAP.md), not here.

| Notebook | Question |

| [`colab_identityresolution.ipynb`](colab_identityresolution.ipynb) | Do reported site positions validate against UniProt sequences? |

Their JSON outputs are the first artifacts of the intended data model, version-controlled under [`data/curation/`](data/curation/) (`OPERATIONS.md` §2):

| Record | Captures |
|---|---|
| `curation_*.json` | How the experimental design was established, and on what basis |
| `analysis_*.json` | Every choice that determined a result — quantity, thresholds, imputation seed |
| `resolution_*.json` | What identity resolution found and where it was uncertain |

Under invariant I9 the graph is regenerable from raw files and the schema. The curation records are the exception — they are human judgement and cannot be recomputed.

Source data is not committed. The notebooks download it from PRIDE; see `.gitignore`.

## Design principles

One line each. Each is enforced by a numbered invariant in [`ONTOLOGY.md`](ONTOLOGY.md) § Invariants, which is where the detail and the enforcement rules live.

- **Evidence and annotation never share an edge type.** What was measured stays distinguishable from what the literature claims.
- **Nothing is asserted beyond what the data supports.** Ambiguous modifiers, unattributed enzymes, razor-picked proteins and imputed values all carry their status wherever they appear.
- **Provenance includes human judgement.** A design inferred from a methods section is recorded as an inference, not adopted silently.
- **Assertions are append-only.** Revision supersedes; retraction propagates to derived figures and reports.
- **Pipelines change; identity does not.** Search engines and statistical tests sit behind registries. Accessions, sequence versions and relationships do not move.
- **The graph is derived, not authoritative.** It rebuilds from raw files plus curation, so schema change is a compute cost rather than a migration.

## Working conventions

- One fact, one home. Cross-reference; never restate. Duplication is a defect, not redundancy.
- Documents carry a header block with status, version and dependencies. Update `last reviewed` when you touch one.
- Amend the document before the code, never after.
- Decisions are append-only. A settled choice is superseded by a later record, never edited.
- Real identifiers only. Never invent an accession or ontology term to fill an example — mark it synthetic or leave it blank.
