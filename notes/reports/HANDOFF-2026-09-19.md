## 4. The two live contradictions

### ADR-0035's premise is contradicted by the deposit

The record says the PLpro axis is *"three cultures split two ways, not six
independent replicates."* The deposit's sample-processing protocol says
**"five millions cells of each genotype were seeded in triplicate for each
condition (WT or mutant PLpro)"** — twelve separately seeded dishes, no lysate
split.

**So the design is representable, and `WALK-STANDARD` v2's R5 FAIL on
`PXD026748` falls with it** — R5's motivating instance, for the second time after
v1's `PXD074990`.

What survives is narrower and still real: whether same-index replicates were
processed as blocks is unstated, the schema could not record a block if one
existed, and the publication does not say which model its ANOVA used.

**Decide at ADR-0035's review.** The record is Proposed; this is what the
round-trip is for. R1 (Sample is the material measured) is unaffected.

### The search database contradicts itself across sources

The paper's Data availability says *"human, including isoforms and unreviewed
sequences."* The deposit's PRIDE text says **Swiss-Prot, 20,621 sequences** —
canonical reviewed only. Zero isoform candidates in 1,185 measured says the
deposit is right.

## 7. Next, in order

### 0. FIRST — the shotgun arm, and the wiring gap behind it

`20210616_Shotgun_PRIDE.zip` holds `proteinGroups.txt` (11.2 MB) — the protein
abundance baseline for the same twelve-run design, in the same deposit, with the
conditions in the filenames. **The files are on disk.**

**`MaxQuantProteinGroupsAdapter` is fully written and has never been reachable
from an ingest.** `bzk/rebuild.py:184` constructs `MaxQuantSiteAdapter`
unconditionally and returns `adapter if adapter.sniff(path) else None` — one
adapter, one branch. Its own docstring says selection should be *"by `sniff` on
content, never by filename"*, which is a dispatch over adapters. The design was
written; the second branch was not. Both adapters expose `sniff`
(`maxquant_protein_groups.py:161`, `maxquant_sites.py:248`).

**Why this is first, ahead of the ADR work.** It makes I4
`protein_adjusted = 'applied'` reachable, and with it **I21**, which ROADMAP
records as exercised by constructed cases only — no writer in the repository
emits an `ADJUSTED_BY` edge, and all 1,362 shipped results are `not_applied`.
The anchor cannot do this: its diGly and proteome runs are separate deposits with
separate sample sets, so there is no sample to key a cell to. `PXD026748` has
both arms under one design.

It is also the protein-abundance confound control for the 2,166 site claims. A
site rising because its protein rose is not an ISGylation finding.

**Three pieces, in order, and the first should be its own commit:**

1. **Wire the dispatch.** Try each adapter's `sniff`; take the one that
   recognises the file. It touches the ingest path for every deposit, so run the
   full suite under `.venv/bin/python` — NOT `python3`, see §3.
   Justifiable without reference to this deposit; burying it in a `PXD026748`
   commit hides why it moved.
2. **A second curation record.** One record carries one `file` and one
   `content_hash`, so the shotgun arm is its own record under
   `data/curation/`'s `<kind>_<accession>[_<qualifier>].json` convention — not an
   extension of `curation_PXD026748.json`. Twelve runs, same four conditions,
   `basis: filename_inference`. **`tests/test_curation_loader.py`'s record-count
   pin moves 5 → 6**; it is designed to trip.
3. **Ingest, and check whether `protein_adjusted = 'applied'` is actually
   reachable.** That is the point of the turn, and it has never been tested by a
   real writer.

**Register expectations before running**, as `walk/PREREG-PXD026748-ingest.md`
did — and note that three of that file's six figures missed, two of them because
the reviewer's basis was wrong rather than because the deposit surprised anyone.
Widen accordingly.
